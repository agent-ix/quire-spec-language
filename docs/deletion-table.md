# Deletion table for the Layer 4 old-architecture units

This is the row-level table for the units the Layer 4 deletion train removes (D-S2, 2026-11-04, QSL main 6a5acbad7). It refreshes the 326-row code-derived inventory against main. ADR-011 "Deletion order of the remaining old-architecture units" fixes the order. FR-499 owns the per-unit dispositions, FR-500, FR-513 and FR-525 map legacy criteria to successors, and FR-521 owns the quire-protocol gate.

## Status words

- GREEN: every successor criterion named in the row is tagged by a test outside the deleted files, and each of those tests passed by name on main (`cargo test --workspace`), or by its named ignored lane (the Makefile target that runs it).
- TICKETED: a successor exists in part; the uncovered criteria are named and a named open ticket owns them.
- KEEP: the file or surface stays (a gate or a consumer names the condition).
- RETIRE-RULED: the behavior ends with its carrier under a ruling cited in the row. No successor test exists. The owner sees these rows as sunsets.
- NO-SUCCESSOR: no green successor test and no open ticket. The behavior is listed in Part C with a recommendation.
- OWNER-DECISION: a sunset candidate the owner decides.
- REOWN-OR-RETIRE: a test file of the deleted lane; the deleting change re-tags its criteria on the successor test or retires them (FR-499 behavior bullet 2). Not an owner decision.
- GATE-OR-EDIT: a gate, an edit task or a post-deletion check, not a behavior (Part E). Part E rows are listed in Part E only and carry no count in Part A.
- NO-BEHAVIOR: nothing to protect. DUPLICATE: counted in another row.
- RED: a successor test fails on main.
