## Summary

Ticket: STD-113. PR: quire-spec-language#1086, head 626b08692, scoped to `git diff refs/remotes/origin/main...626b08692` (five files, +19/-16). Spec-only. It cites QSpec PR #296's `Quantity<u>` type form: FR-185's 'Quantity-typed parameters' section types a quantity operation parameter as `Quantity<u>` with quantity-literal supports, keeps integer supports for the `Millis = Int[1, 12]` fixture, and adds FR-185-AC-8 and TC-620 step 8 (waiting on QSL intake); FR-091's type-form lookup paragraph and OQ-11(d) now name `Quantity<u>`; FR-098 and TC-906's dependency notes cite QSpec FR-142. Base review: agreement with QSpec #296's terms and refusal codes, the layer that resolves an operation parameter's type (FR-056 against FR-091), the AC-8 and TC-620 step 8 vectors, the Millis steps 1 to 7, and engine reality. Independent checks. (1) QSpec #296 adds `'Quantity', '<', qualified-name, '>'` to the complete-V1 `type-ref`, a source production; its FR-142 section, AC-11/12 and TC-187 U30/U31 use a source parameter `d: Quantity<ms>` and a source function. Terms agree: `Quantity<u>` over a unit, unit namespace only, another unit of the same dimension refused, `Quantity<Time>` of ADR-024 7.2 not a type form. (2) The complete-V1 grammar has no operation-signature declaration: 'Domain types named from an imported domain package give model-owned parameter domains', and the TC-620 fixture's `Service` is a domain package whose `attempt` parameters carry `typeRef`s. (3) QSpec's model documents have ten meanings (event-type, namespace, object-type, persistence-interface, population, process, record-value-type, state-machine, value-type, variant-type) and none declares a dimension, a unit or a quantity type; FR-056's natives (UUID, Integer, String, Boolean, Timestamp, Rational, Decimal, Float32, Float64, Text) hold no quantity. (4) QSpec FR-405-AC-3 keeps value-outside-type for a support outside the parameter's type. Engine probes on main 812c95430 (scratch clone, qsl-semantics TC-620 fixture, a domain package `Service` with `dimension Time; unit ms : Time = rational(1, 1);` in the unit): (A) `function f using v(d: Quantity<ms>): Boolean pure { true }` is refused by S1, invalid_syntax/UnexpectedToken 'expected `)`' at `<`, so no `Quantity<u>` type-ref parses today; (B) `random Server::attempt(d) ~ { 1 ms: 90, 3 ms: 7, 12 ms: 3 };` over the `Millis = Int[1, 12]` parameter parses and S3 refuses each support invalid_probabilistic_model/value-outside-type; (C) `{ 1 s: 90, 3: 7 }` refuses missing_declaration/missing-name at `1 s`, because the fixture declares no unit `s`. Gates on the head: make check-spec-validation exits 0 with 17 warnings, none in the changed files. tools/check-index-completeness.sh passes. quoin 0.28.3, quire 0.36.2 (engine 0.50.2). Methods: spec-review/base (SR-13421), spec-review/ears (SR-13422), spec-review/integrity (SR-13423). code-review and gap-analysis were not run, because no code or test file changed.

| FND-001 | high | FR-185 types a quantity operation parameter as `Quantity<u>` and says only QSL intake is missing, but no specified form lets a domain package's parameter name a unit, so AC-8 has no path to pass. Operation parameters are not declared in complete-V1 source: the shared grammar has no operation-signature production, and a parameter's domain is the `typeRef` of the imported domain package (the TC-620 `Service` fixture is one). QSpec #296 defines `Quantity<u>` only as a source `type-ref`, over a unit the source declares, naming that unit's node (keyed over the unit's source owner, FR-091-OQ-3). A domain package is admitted against its own digest before the unit's declarations exist, it cannot name the importing unit's `ms`, and no QSpec model-document meaning declares a unit or a quantity type (the ten meanings listed in the Summary). FR-056's natives hold no quantity either.
