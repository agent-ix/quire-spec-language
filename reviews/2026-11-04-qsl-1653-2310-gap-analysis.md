# Gap analysis of QSL-1653 imported-function call-site selection (quire-spec-language PR 2310)

## Summary

Plan completion: not assessed. This PR changes only the spec. FR-121-AC-32 to AC-36 have no
implementation and no tagged test yet, which is expected because the code comes with the QSL-1653
coding slice. Every new AC is traced to TC-516: steps 27 to 31 map one to one to AC-32 to AC-36, and
TC-516's scope line lists them. Each expected result is something the test can observe.

The ticket outcome (QSL-1653, read as data) asks for a public API that returns the declaring package
identity and the function occurrence, both from the lock CG uses. `ImportedFunctionSite` gives
`library`, `package_id`, `package` and `function`, all from the unit's own closure compile, which
meets that outcome.

FR-121 and `qsl-replay/src/call_site.rs` already disagreed before this PR. The spec's `CallSite` has a
`package_id` member, while the code's `CallSite` has only `package` and `site` (call_site.rs:142). The
spec's `FunctionSite.function` and its parameters are `WireNodeId`, while the code uses `NodeKey`
(call_site.rs:150-168). The PR follows the spec's shape and adds no new kind of disagreement.
`ImportedFunctionSite.package_id` sits in the same place as the existing `CallSite.package_id`, and
AC-33 needs it to key a replay, as AC-4 already does. The implementing slice has to settle the
existing disagreement either way, so this PR does not need to.
