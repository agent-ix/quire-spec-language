# Spec review of TC-144 and TC-149 evidence-route re-homing (quire-spec-language PR 2307)

## Summary

One pass over `git diff origin/main...HEAD` at head 3f375ceff42918633555690c3631b8832a6b4a56.
Checked against FR-052-AC-9 to AC-14, FR-053-AC-7 to AC-9, FR-501-AC-19 and "Canonical order",
FR-516 (Outputs, AC-16, AC-19, AC-20, AC-40), FR-524 (contradiction, surplus), FR-526, the code on
main (`qsl-eval/src/temporal/evidence/{call,request,activation,trigger}.rs`) and the tests of PR
2306 (`qsl-eval/tests/it/checked_route_trigger.rs`, read, not run: the build needs private
dependencies; the causes it quotes were checked against the code by reading).

Verified true: every cause token the rows name exists in `call.rs` with the stated trigger:
`activation-mapping-missing`, `activation-mapping-mismatch`, `trigger-required`, `trigger-unknown`,
`no-ledger`, `predecessor-unknown`, `predecessor-not-latest`, `unchanged-input`, `surplus-capture`;
the contradiction refusal is `invalid_runtime_input`/`invalid-value` with `contradicted_identity`
(cause `delivery-contradiction`); `EmptyIdentity` is returned by `SemanticTriggerIdentity::new` and
`EvidenceRequest::trigger_of`. The code's relation check order (no-ledger, predecessor-unknown,
predecessor-not-latest, unchanged-input, correspondence-changed) matches row 9's sequence, and a
Superseding naming another clause finds no entry under that obligation and gives
`predecessor-unknown`. A delivery with one capture fewer gives `Unavailable` with a `Missing`
capture fault (`activation.rs` establish). `ClauseRunRequest` has no trigger or relation input;
`EvidenceRequest` has no truth, settlement or support member. The tests of 2306 assert the same
causes as rows 4 to 6 and use only symbols that exist. Every cause row 5 and 6 name is exercised.

TC-144 row 5 against FR-501-AC-19: no conflict. AC-19 lists stamps 5, 0, 2; row 5 lists 0, 5, 2 with
`level` 0, 2, 1; sorted by stamp this is stamps 0, 2, 5 with `level` 0, 1, 2, which is trace A, and
FR-501 "Canonical order" says the outcome and `result_identity` do not depend on the listed order,
so row 4a's outcome and identity follow. The row is correct; its clause-route test is missing, as
the PR says.

Coverage: every FR-052-AC-9 to AC-14 still has a row (AC-9 rows 1, 2; AC-10 rows 3, 4b to 4d, 4g;
AC-11 row 6; AC-12 row 9; AC-13 row 8; AC-14 rows 4h, 7). FR-053-AC-7 to AC-9 each have rows, with
the gaps in FND-002 and FND-003. No ticket id appears in the diff. `quire validate` exits 0 on both
files (only the module duplicate-archetype and inline-data-schema warnings, also present on main).
FR-052, FR-053, TC-124, TC-140 and TC-141 do not name `run_clause` for these rows.
`tests/it/compiled_protocol_v2.rs` does not name `run_clause` either; see FND-006.
