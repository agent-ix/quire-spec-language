## Summary

Ticket: STD-218. PR: quire-spec-language#1087, head 7f7f7545b, scoped to `git diff refs/remotes/origin/main...7f7f7545b` (one commit, three files, +34/-2). Spec-only. It adds a 'What S3 decides and what EN-1 decides' section to FR-220, one sentence to ADR-025 MA-2, FR-220-AC-7 to AC-10, and TC-665 steps 6 to 9. Merged code PR #1053 (QSL-558) depends on this text. Base review: whether what the PR assigns to S3 can be decided without object identity, measured against the S3 engine on main. Measurement. The S3 engine on main (the code of PR #1053, merged as 1bcc1584d, an ancestor of 812c9543) was run in a scratch clone at 7f7f7545b. A probe test was appended locally to qsl-semantics/src/check/protocol_memory/tests.rs and then reverted. It reuses that file's own fixtures (`litmus`, `sb`, `store_buffering_model`: `Cell{v,w}`, `Core{r}`, `Cell::set`, `Core::read(src)`, `Cell::both`, `Cell::flip`). The results are the same under `sc`, `memory tso` and `memory ra`. AC-7, two `relaxed` `Cell::set` attempts by `X` in the two branches: admitted, each `class: None`, `ordering: Relaxed`, atomic. AC-8, `Ly` then `Core::echo` (which reads `r`) in one branch: admitted, every class `None`. AC-9 (and AC-1), `SB` with `release`/`acquire`: admitted, `Sx`, `Ly`, `Sy` and `Lx` all `class: None`. AC-10, `attempt Lone` outside every `parallel` with `ordering seq_cst` (and also with `relaxed` or `acquire`): refused `ill_typed`/`operator-ineligible`, `AccessOrdering{attempt: "Lone", class: Local}`, located at the ordering word. Without an ordering it checks. Beyond the new ACs: `Cell::both`, which writes `self.v` and `self.w`, is admitted under `memory tso`, although AC-3, MA-4 and FR-220's Access shape say S3 refuses it. `Cell::flip`, an RMW, with no ordering is admitted, although MA-3 and AC-2 say S3 refuses it. `SB` with its loads at `ordering release` (`Core::read` reads `src.v` and writes `self.r`) is admitted, although MA-3 and AC-2 say S3 refuses a load with `release`. A store with `acquire`, a read-only attempt with `release`, and a no-data attempt with `relaxed` each refuse `ill_typed`/`operator-ineligible`. The engine's own 10 protocol_memory tests pass. The full results are in sr-1087-tools/probe-results.txt. Code search: no code on main implements EN-1 sharing, branch-locality or `WeakAccessShape`, so the EN-1 halves of AC-8 and AC-9 cannot be measured today. Text checks. The grammar is `attempt N by R on M::T::op`, with no receiver expression, and ADR-027 ST-1 draws the receiver from the finite domains at each application. So the claim that S3 has no object identity holds, and so does MA-1's sharing over instantiated footprints. FR-226's load-buffering note (merged with #1083) already puts the shape at EN-1's pre-check, which agrees with this PR. `ill_typed`/`operator-ineligible` is the refusal MA-3 already uses for an ordering, and it is what the engine returns for AC-10. Methods: spec-review/base (SR-13424), spec-review/ears (SR-13425), spec-review/integrity (SR-13426). code-review and gap-analysis were not run, because no code or test file changed. Gates on the head: make check-spec-validation exits 0 with 17 warnings, none of them in the changed files. tools/check-index-completeness.sh passes. quoin 0.28.3, quire 0.36.2 (engine 0.50.2).

| FND-001 | high | The new bullet says S3 decides 'the access class over the operation's fields (load, store, RMW or local)', but MA-2 defines the class over the shared footprint, and the preamble just above it says S3 cannot tell shared from branch-local. Over the operation's fields, SB's `Ly` (`read(y)` on `c1`: it reads `y.v` and writes `c1.r`) is a read and a write of two fields. It is a load only once `(c1, r)` is known to be branch-local, which S3 cannot know. A two-field read-write like that is the register-read-again shape of AC-8 and AC-9, so classifying over fields either calls `Ly` an RMW or two-location access (and breaks cases (b) and (c) of STD-218) or calls it a load by guessing. The engine on main records `class: Local` for an attempt that touches no data place and `None` otherwise. Measured: SB under `sc`, `tso` and `ra` gives `None` for all four attempts. ## Verdict

Not mergeable. The PR has the right premise: S3 has no object identity, so sharing belongs to EN-1. But its rule still gives S3 two things that depend on sharing, the access class (FND-001) and the two-shared-fields shape (FND-002), and the merged engine decides neither. Ordering eligibility that depends on the access kind is left with no owner (FND-003). AC-7 and AC-9 put an EN-1 result in an S3 AC (FND-004). What holds: each new AC's fixture is admitted or refused exactly as stated at S3 today (AC-7, AC-8 and AC-9 admitted under `tso` and `ra`; AC-10 refused `ill_typed`/`operator-ineligible` naming the attempt, at the ordering word). The claims about object identity and the receiver are true of the grammar and ADR-027 ST-1. The AC-10 refusal code is the one the engine returns and the one MA-3 already uses. The split agrees with MA-1 and with FR-226's EN-1 load-buffering note. This needs a decision. The STD-218 ruling text keeps 'the two shared fields of the receiver shape' at S3. The merged code (PR #1053, whose body records the planner's split) defers that shape and the access kind to EN-1. The PR's own preamble argues that neither can be decided at S3. This review recommends aligning the spec with the code.
