# SR-12245: Code review (Rust lane) of QSL-570 part 2a: EN-4 check_statistical over a model subject and the step-at-a-time FR-188 sampler (PR #1132)

## Summary

Ticket: QSL-570. PR quire-spec-language#1132, branch qsl-570b-impl, head 44fb756e5. The review covers `git diff origin/main...HEAD` only: 18 files, +1830/-142. The rust-review lane is folded into this file. The spec was read on this repo's `origin/main`: FR-186, FR-188, FR-189 (AC-1..14), FR-190 to FR-193, FR-126, FR-196, ADR-018 SM-1/SM-3/SM-4, and ADR-024 PM-*, PF-*, ST-*, SV-*. QSpec FR-364 was read by id, read-only.

No gates or builds were run, per the brief (load average 14). The whole review is a code read. The gate stages were checked by reading the code (see Verdict).

## Verdict

**NOT MERGEABLE: one major (FND-001).** A bounded event never closes at a terminal model state. EN-4 instead reads the terminal state's truths again on each stutter step, up to `h`. ADR-018 SM-4 says a behaviour under a bounded profile that reaches a terminal state is a closed finite execution, read by the closed-boundary rule. FR-126 and FR-196 close the monitor there with the false extension, and EN-5 does the same (`closes_at_terminal`). So for any bounded-event claim whose samples reach a terminal state inside the horizon, EN-4 can decide the opposite of EN-5 and FR-126. For example, `always[0,h] holds(p)` with `p` true at a terminal state before `h` is true in EN-4 and false in EN-5. No test reaches a terminal state under a bounded event, so the suite cannot catch this.

What is sound:
- **Step-at-a-time sampler, byte-identical.** `sample` now runs on `ProbabilisticSampler`. The generator check comes first, then the start's state key, then per step: the cancel poll, the enabled actions, a stutter step at a terminal state, and `take_step` with the same `StepDraws{seed, trace, step, choice: 0}`. Digests are summed even when `take_step` fails, and the post-state key is computed with the same `broken()` mapping. The order of draws, the choices, the post digests and the digest count are all as before. The cache keys on the full state-key bytes and stores only a successful `enabled_actions` (an `ExpansionStop` is not cached). `ModelSystem` is borrowed immutably and each expansion runs under a fresh meter, so caching cannot change when a meter stop happens. The existing `sampled` tests are unchanged.
- **Draw coordinates.** Step `i` of a sample draws at `StepAt{seed, trace, step: i}`, where `i` is `cursor.steps.len()`, and the trace index comes from `check_sampled` (`i·m + j`). A regeneration walk draws at `(seed, j, taken)`. The undefined-witness re-walk redraws the same coordinates from the same start, so its steps are the walk's own steps.
- **Exact path probability.** Every probability, reward and fraction is a `Rational`. No float is used anywhere in `model.rs`.
- **Measures (ADR-024 PF-2).** Activation is the first `a` where `from` holds, and the end is the first `b >= a` where `until` holds, with `a = b` giving 0. The reward is added only for steps into positions `a+1..b` (`if active` is checked before `active |= from`). No `a` gives not activated, and `a` with no `b` gives censored. A censored value fails `<=` and passes `>=` (`compares`), and `MeasureEvent::holds` gives the reduced quantile event. The window continues on stutter steps, as PF-2 states for measures.
- **Weighted fraction, `h + 1` steps.** Each position `0..h` is weighted by the step that leaves it, so the step leaving `h` is drawn. This follows PF-2 (disclosed choice 3).
- **Witness side.** `violating` on `Sample::Measured` keeps `!holds` for `>= q` and `holds` for `<= q`/`< q`, carrying the measure (or `Censored`). An undefined sample is always kept as the undefined witness and decides Rejected (PR 1's seam, unchanged). An undecided successor ends the test `UndecidedSuccessor`. NotMarkov, the total above the draw range, an expansion stop, cancellation and a generator mismatch all end as a stop, an unsupported result or a refusal, never as accepted or rejected.
- **Bounds.** Each sample reads at most `h + 1` positions (`h + 2` for a weighted fraction). Walks are bounded by `max_draws` and `max_cycle_steps`. Cancellation is polled before each step.
- **qsl-replay surface.** `UnsettledRefusal` replaces the bare `NotStatisticalRequest` error. The `Admission` and `RequiresBound` refusals have no FR-192 row. `UndefinedLocus::ClaimPredicate` is added to both exhaustive matches (`replay.rs`, `certificate/simulation.rs`). Every other match on `UndefinedLocus` in the workspace has a `_` arm or a single-variant pattern.
- **FR-100-AC-8.** The new `qsl_replay` re-exports (`ClaimPredicate`, `UnsettledRefusal`) are qsl_replay types, and nothing is added under `spine`. `StatisticalUnsupported::NotMarkov(Box<NotMarkov>)` and `StatisticalRefusal::RequiresBound(RequiresBound)` name `qsl_eval` types in `qsl_replay::statistical`. That module already did so, and the arch-lint check (`spine_surface_qsl_eval_findings`) scans only `spine` and the crate-root `pub use` items.
- **Panics.** There is no `unwrap`, `expect`, indexing or `unsafe` in production code. `let [from, until] = truths[..] else` is a slice pattern with an `else` branch. All arithmetic is exact or checked (`checked_add`, `u64::try_from`).
- **Gate stages, by reading.** The new public items all have docs (`missing_docs` is `-D` under clippy). The new `Result<_, SampleStop>` methods carry the crate's `result_large_err` allow. `SampleHalt`/`Ended` only gain a boxed payload, and `RequiresBound` is a `BTreeMap` (24 bytes), so `StatisticalRefusal` stays under the large-error threshold. The shipped code adds no string-literal comparison (string-edge), no seam-enum match (seam-probe) and no checked-type construction (TC-244). `plan.rs` going from `pub(super)` to `pub(crate)` trips no `clippy::all` lint. The PR reports `cargo check --workspace --tests --all-features` clean after the merge of main, and clippy `--all-features -D warnings` clean at 4061fd67b. The merge since then touched no file in this diff. I expect no gate-stage failure.

The seven disclosed spec-gap choices, judged against the spec:
1. *Never-activating accumulate/steps under a probability bound treated as not counted.* A spec gap. The choice contradicts the unconditioned measure of PF-3 (FND-002).
2. *Zero-total weighted fraction becomes an unsupported stop that settles `failed`.* Unsound as a reading. Zero over zero is an undefined evaluation, which SV-11 decides Rejected (FND-003).
3. *A weighted fraction draws `h + 1` steps.* Sound. PF-2 requires it, and FR-189's "`h + 1` positions" text is what needs amending (FND-007).
4. *The FR-126 default automaton budget, with exhaustion as an internal failure.* Contradicts FR-126, which settles exhaustion as `ResourceExhausted` (FND-004).
5. *`PredicateReading::Refused` treated as an evaluator fault.* Inconsistent with FR-196, where EN-5 returns `PredicateRefused` (FND-006).
6. *No FR-192 row for Admission/RequiresBound.* Sound. ADR-016 EX-8 makes `RequiresBound` a disposition, and FR-192 should list both rows (FND-008).
7. *The claim-predicate locus spelling.* Acceptable for now. QSpec FR-364 has no such locus kind, and FR-193 replay needs one before it can rely on it (FND-008).

| FND-001 | high | A bounded event is never closed at a terminal model state. In `Shared::formula`, `advance` takes the stutter step that `ProbabilisticSampler::step` returns at a state with no enabled action. The monitor then reads the same letter at every later position up to `h`, and `false_extension_rejects` runs only after position `h`. ADR-018 SM-4 says: "Under a bounded profile, a behaviour that reaches a terminal state is a closed finite execution, read with that profile's closed-boundary rule". FR-126 closes the TP-2 monitor at a terminal model state, and FR-196 requires "FR-126's closure at terminal model states". EN-5 does this through `closes_at_terminal`/`close`. EN-4 therefore gives the wrong event value whenever a sample reaches a terminal state before `h`. `always[0,h] holds(p)` with `p` true there is true in EN-4 and false in FR-126 and EN-5. `eventually[0,h] holds(q)` with `q` false there agrees only by chance. Fix: after reading a terminal position's letter, close the running monitor with `false_extension_rejects` and stop reading. A terminal position is one whose step is `TransitionId::Stutter`, or check it before advancing. Add a model-backed test that reaches a terminal state inside the horizon and asserts the closed value. Measures and fractions continue on stutter steps, as PF-2 states, and are unaffected. | qsl-analyze/src/statistical/model.rs:610-646; qsl-eval/src/simulation/sampled.rs:337-363 |
