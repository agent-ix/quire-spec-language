## Per-check results

(1) Rule. FR-464 "Level": a channel enters at `size(C0)`, `C0` being `over`, the activation binder (`each` trigger) and every protocol capture binder; two binders of one name readable at one place refuse `ambiguous_declaration`/`ambiguous-name` at the node that introduces the second. A replicated role's binder is read only at the `role-lifetime` stage and a role also enters at `size(C0)`, so it is a sibling of the channel binder, not part of its scope. IR main (1221a1b) `check_declaration_slots` introduces a channel binder over `base = c0` only and `introduce` compares names against that set; role, channel and control binders are all introduced independently against `C0` or the control's input. QSL matches this: `readable` is Input, ActivationParameter and top-level (scope none) Capture. Binder kinds excluded and why: RecordBinder (a run-tree or finish binder, readable only inside the control tree), Trigger/RetryParameter/RecoveryParameter and a capture inside a `compensate` (all in a compensation template's scope, which a channel never sees). Probed through QSL's S3 on the recovery fixture: a FIFO binder named like `input` or a top-level capture refuses with one `ambiguous_declaration`/`ambiguous-name`; the same name as the compensation capture, `failure` (template record binder), `trigger`, `current_attempt`, `prior`, `recovery`, a run-tree record binder, `outcome` (finish binder), a role name, the channel name and the control names are all admitted, as IR main would. Two channels with one fresh binder name `m` are admitted (each channel has its own scope); two channels both naming `input` give two refusals, one per binder. Too narrow: none found (every C0 member is covered; a clash among C0 members themselves is the existing Shadow refusal). Too broad: none found. Location and order: the refusal is at the binder name of the second (the FIFO binder), `loci` are `[earlier, later]`, and it joins the existing `(Span, CheckRefusal)` list that is sorted by span start with a stable sort, so it sits in source order among the other protocol-control refusals; the pushed order (after duplicate channels, before messages) only matters for equal spans, which cannot occur here. The key of a clashing channel adds no second refusal (the new test asserts exactly one).

(2) Mutation of the new code against `a_fifo_binder_named_like_a_readable_binder_refuses` (qsl-package). Killed: call deleted; Input excluded; ActivationParameter excluded; Capture excluded entirely; RecordBinder admitted into `readable` (killed by the `outcome` case); loci order swapped; `name` emptied; loci reduced to one. Survived: Capture filter `scope.is_none()` changed to `true` (a compensation capture would clash); Trigger, RetryParameter and RecoveryParameter each moved into `readable`. These four are the justified exclusions and no test admits a FIFO binder named like a compensation capture, trigger, retry or recovery parameter (FND-001 below). The three new table cases: with the `ProtocolReference` arm of `reads_declaration` removed, `every_remaining_unwritten_construct_refuses_typed_and_writes_no_clause` fails (killed). With the `Dispatch` arm removed everything passes (survivor, see (3)).

(3) The Dispatch gap. `NodeKind::Dispatch` is made from a `receiver.member(args)` call whose receiver and member match a `DispatchOperation` that the model bridge (`link_dispatch`/`merge_linked`) puts in the package. So it is reachable from user text, but only in a package whose model has an operation family (a redefined operation chain, as in `tests/it/dispatch_linking.rs` over `config_version_document_with_operations`) and only in the complete profile; the emit tests' fixed `model()` document has none, so the coder could not write it. The arm is therefore correct, not dead. Recommendation: keep it (dropping it would let a dispatch read through the emitter as if it were written) and cover it, when QSL-1121g emits function and dispatch reads, with a test built on the `dispatch_linking` fixtures or on `owners.rs`'s `checked_dispatch_operation` API route; until then it stays an acknowledged survivor, LOW. The spec sentence now says "dispatches a call", consistent with the code.
