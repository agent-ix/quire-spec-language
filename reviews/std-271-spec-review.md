# SR-15710: Spec review of quire-spec-language PR #1244: STD-271

## Summary

Ticket: STD-271 (unblocks QSL-911). Sub-analyses folded in: integrity, EARS, criterion strength, dependency, scope-boundary. `make check-spec-validation` (QSPEC_DIR=~/dev/quire-specification) passes at the head with no diagnostic on the touched files. TC-1161 and FR-255-AC-12/13 are unique across all 46 open PRs; no other open PR touches FR-255. The head's parent is 48108c9c1; origin/main is one commit ahead (43f4e2086, #1236, unrelated files) and merges cleanly, so the PR body's "origin/main is an ancestor" no longer holds.

Grounding: all 28 rows match their owner FR's member name and default. Code: `ModelCheckLimits` (7 members, defaults 10000000/100000000/1048576/64/4096/65536/16777216), `StatisticalLimits` (2^24, 2^26, 2^24; code already writes `statistical.*`), `ScheduleLimits`, `ExpansionLimits` (no default). Spec only: `ExactProbLimits` (FR-203), `TimedSampling` (FR-254), `ZoneCheckLimits` (FR-239), `CertificateCheckLimits` (FR-245), `max_window_values` (FR-194), `hybrid.limits` (FR-250). No limits struct is missing from the table. The method bounds `max_live_instances`, `max_store_buffer` and `max_messages` are `ModelCheckRequest` members that settle V-6, which supports the exclusion on the QSL side. QSpec FR-461-AC-6 uses `model_check.max_states` as the PR says. The backend-provider `SettingName` pattern `^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)+$` rejects a bare `work_units`, which confirms the ungrounded meter gap. The dependents #1254 (`certificate_check.max_certificate_bytes`/`_edges`) and #1256 (`expansion.max_candidates`) use names that match the table rows.

## Verdict

**NOT MERGEABLE as written.** The table is complete and grounded in the owner FRs. Two problems block the merge. AC-12 cannot pass, because the engines it covers also stop at limits that sit outside the table (FND-001). The exact-probabilistic names contradict the QSpec wire schema, which owns them (FND-002). Both need a decision, and the meter-setting gap stays open for QSpec. The other findings are minor wording and traceability fixes.
