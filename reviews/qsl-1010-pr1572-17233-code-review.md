## Summary

Ticket: QSL-1010 (QSL-1083). The encoder is a faithful encoding of FR-315 "Hyper self-composition queries"; no wrong-output defect was found. The main risk, an unsound script read by CG IR-974 as a k-induction proof, was attacked directly: no SMT solver exists on this machine (no z3, cvc5, python bindings), so a scratch test (not committed) ran the PR's own solver-free checker (`script_search.rs`) over the encoder's scripts and compared each verdict with an independent explicit-state oracle written from the spec text (joint states over the vault's (h, l) in {0,1}, tuples ordered and filtered by hand-coded `mu_U`, undefined tuples kept and failing at i+1, the monitor table derived by hand from `always (A implies always B)`, step queries over all pairwise-distinct joint states and free `m0`). 96 cases: 4 vault postconditions (`l = i`, `l = h`, `l = 1 - i`, `l = pre(l)`) x 3 matches (none, equal inputs, FR-176-AC-4's undefined-on-step(0) divisor) x 4 bodies (`always l`, `always (l and h)`, `always (h implies l)`, the monitored `always (h implies always l)`) x depth 1 and 2 x base and step: 0 mismatches. This covers the lexicographic joint disjunction and `mu_U` filtering, stutter, undefined-match failure at i+1, the distinct-state assertion, the initial predicate per trace variable, per-copy reads s<i>.<t>, monitor tabulation, and the `always` fast path (which is sound for any propositional combination of atoms: `land` and `implies` agree with the oracle). A universe {v, w} with instance w reads `s<i>.<t>.w.l` and not `.v.l`. The goldens secure-base-1.smt2 and secure-step-1.smt2 are byte-identical in the first commit (60dda7d9f, where the golden test passes) and at the head, and I read them against the hand-derived table: correct. The meter is one cumulative budget (one `&mut Meter` threaded through every `universal` call). The Faults arms map as FR-315 states. Output is deterministic (BTreeMap/BTreeSet only; the one HashSet is membership-only).

Gates (`flock /tmp/qsl-cargo.lock make ci`, then the lanes after the first red by hand): fmt, clippy `-D warnings` workspace, all tests of both feature lanes, doc-tests (default and all-features, including the three `compile_fail` doctests), qsl-semantics and qsl-cst lanes, test-deep-format, clean-build, seam-probe, string-edge, route-lint, checked-input, refinement-versioning, cargo-deny-bans, ci-docs, arch-lint (canonical-encoder, api-surface-qsl, qualified-core), build-no-std: all green. Red: `xtask` unit tests `string_edge::tests::every_workspace_member_is_a_scan_root` and `typestate_scan::tests::tc_244_only_the_named_stage_constructors_return_stage_types`, in both the default and the all-features lane. Both fail identically at origin/main d9735657c (checked in a clean worktree): they are not caused by this PR, but see FND-005.
