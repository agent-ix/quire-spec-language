# Spec review of QSL-1653 imported-function call-site selection (quire-spec-language PR 2310)

## Summary

One spec-review pass over `git diff origin/main...HEAD` at head cd68ca8f (FR-121 description, inputs,
outputs, five behaviour bullets, refusal-code and settlement lists, FR-121-AC-32 to AC-36; TC-516
scope, steps 27 to 31 and expected results). Checked against ADR-015 D-1 to D-5, ADR-013 QC-10,
QSpec FR-322 (`dependency_reference`, `DependencySelection`, FR-322-AC-26, FR-322-AC-35, read from a
detached worktree of QSpec origin/main), TC-444 step 7, and the qsl-replay, qsl-semantics,
qsl-package and quire-exact code (read only).

The three design choices hold. Selecting the library by `LibraryName` and not by import alias
matches ADR-015 D-2 and D-3. Allowing only direct imports matches FR-322: a `dependency_reference`
whose `package` is not a direct `dependency_selections` entry is refused even when the closure reaches
it. A function the unit never calls can be selected, because ADR-015 D-1 step 4 compiles every
imported library in full. The refusal codes reuse codes the spec already uses.
`missing_declaration`/`missing-selection` and `missing_declaration`/`missing-name` are FR-322's codes
for a `dependency_reference`. `ill_typed`/`operator-ineligible` is ADR-015 D-5's and FR-322's code
for a signature that is not package-independent. The PR adds no compatibility layer and no ceremony.

One blocking defect remains. The PR binds the site's `package_id` to the `package` member of the
`dependency_reference` term. That member is the dependency's name, not its `package_id`.

`quire validate` on both files exits 0. Its only warnings are the module duplicate-archetype warnings
and EARS warnings at FR-121 lines 179 and 273, which predate the PR. `git diff --check` is clean.
