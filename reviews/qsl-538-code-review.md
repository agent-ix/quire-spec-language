# SR-12201: Code review (Rust lane) of QSL-538 E8d FR-169 state-graph certificate and checker (PR #1046)

## Summary

Ticket: QSL-538 (E8d), state-graph half. PR quire-spec-language#1046 at head cbbdfd75b, diff `origin/main...HEAD` only (2 commits, 10 files). Reviewed as code-review with the rust-review lane folded in. Reviewer only: no builds were run. The coder reports clippy, fmt, check and the qsl-replay, qsl-analyze, xtask and `it` tests at EXIT=0 on the final head.

The review focused on soundness of `check_state_graph`: whether a bogus certificate can be accepted.

- **Reachability and closure.** `explore` starts from `ModelSystem::initial()`, recomputes every successor with `qsl-eval`, follows only successors that are members of `closure`, and rejects `SuccessorMissing` when any successor is not a member. So the reached set is exactly the true reachable set, and nothing from the engine is trusted except the certificate's entries. `InitialMissing` is checked first, in digest order.
- **BadState.** An expansion with an undefined or refused contract finding marks the state bad and rejects `BadState` after `SuccessorMissing`. The predicate matches the engine's open-node predicate in `explore.rs` (`undefined.is_some() || is_refused_contract`).
- **PredicateUndefined.** Every written predicate is read at every reached state, with the re-derived `over` binding. `Undefined` or `Refused` rejects.
- **Ranks.** A ranked reached state with `d = 0` must satisfy the target, and one with `d > 0` must have a recomputed successor ranked `d - 1`. Every successor of a reached state is reached and so is checked too. By induction on `d`, every ranked reached state reaches a target. `possible` requires every initial state ranked; `always possible` requires every reached `from` state ranked. Sound.
- **Counts, and departure 2.** Let `c(s)` be the certificate's count, 0 when there is no entry. A `to` state must have count 1. Any other state's count must equal the per-edge sum of its successors' counts, saturated at 2. A `from` state must count 1. States with count 0 are closed under successors and contain no `to` state, so their true count is 0. A non-`to` state with count 1 has exactly one edge to a count-1 successor, and every other edge goes to a count-0 state. The order rule forces that successor's order to be strictly lower, so the chain of count-1 states ends at a `to` state and the true count is exactly 1. Count-2 states are never used to support a count-0 or count-1 state, because the saturated sum would exceed 1, and a `from` state may not have count 2. So exempting count-2 states from `OrderBroken` cannot let a false `unique path` through. The module-doc argument is sound. Edge multiplicity matches: the engine keeps one `GraphEdge` per expansion successor, and the checker keeps one `successors` entry per expansion successor.
- **Malformed.** The closure must be strictly ascending and in the `SimulationStateKeyV1` domain. Rank and count indices must be strictly ascending and `< closure.len()`, and counts must be `<= 2`. All of this is checked before any recomputation. An index outside the closure rejects at `Entry { index }`; other entries reject at the state's `ModelState`. The `state_at` fault path is therefore unreachable.
- **Limits and cancel.** A closure longer than `max_states` stops at once. Reached states count against `max_states` through `admit`, and edges count against `max_transitions` before each increment, the same `>=` convention as the engine's `explore.rs`. Cancel is polled at entry, at each dequeued state and at each predicate read.
- **`expansion_halt` refactor.** It is behaviour-preserving for `check_closure`. The meter, max-candidates, internal-fault and resource-exhausted arms map one-to-one to the old `expansion_stop` arms, and `DigestWire::of` serializes the same fields as before.
- **New rules and loci.** There are six new `CertificateRule` variants and two `CertificateLocus` variants. `CertificateLocus::serialize` handles both new loci, and `Entry`'s index is a decimal string, the same as `ProofStep`'s. The other places that name rules (`outcome.rs`, `proof_result.rs`) are test vectors, not matches, so they need no change. The new spellings are covered by `state_graph_rules_and_loci_write_their_wire_spelling`.
- **Engine production.** An honest certificate always passes. Certificates are produced only when `complete()` holds: the run ended `Completed`, has no open node and no refused instance predicate. So partial or open nodes never carry a certificate. Ranks come from target BFS distances (`d_p`, or `backward(targets)` for `always possible`), so every `d > 0` node has a `d - 1` successor. On a complete run, `H` is exactly the set of nodes that reach a `to` node. Every `H` node therefore counts at least 1, and no count-0 entry is emitted. Nodes in cyclic components count 2. Count-1 nodes are acyclic singletons, and all their `H` successors come earlier in the reverse topological positions. Successors outside `H` have no entry and count 0, so the checker's per-edge sum equals the engine's sum over `H` edges. `to` nodes are never cyclic, because their outgoing edges are dropped from `H`.

No major finding. All findings are low: idiom, duplication and undeclared spec drift.

## Verdict

**PASS: mergeable. No major or high finding.** `check_state_graph` cannot accept a bogus certificate, because each rule's acceptance condition implies the claim over the recomputed reachable set (argument in Summary). The departure that exempts count-2 nodes from `OrderBroken` is sound. Every certificate the engine produces on a complete unreduced run passes the checker. The `expansion_halt` refactor does not change `check_closure`'s behaviour. All five findings are low and can be fixed in this PR or recorded.
