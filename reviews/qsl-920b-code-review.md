No gates were run, per the brief. One narrow run: `cargo test -p qsl-eval --lib` filtered to `simulation::model::probabilistic`, `simulation::sampled` and `simulation::choice`, through `locked-build.sh`. Its result is in the Verdict.

## Verdict

**FAIL (one major).** FND-001 blocks. When a contract is undecided, `actions` and `weighted_steps` silently leave out that application or post-state candidate. They then report probabilities and a Markov verdict computed over an incomplete successor set. FR-187 says an undecided conjunction stops with `ContractUndetermined`. Everything else is medium or low.

What is sound:
- **Exact probabilities.** A `Draw` is the product of PM-1 probabilities over every support vector. A random parameter cannot be read by a precondition (S3 `random-read-in-precondition`), so every draw of a scheduled identity is enabled or none is. The draws of an action therefore sum to 1. `weighted_steps` gives each step `w(o)/Σw · 1/|E_o| · p(draw)` in exact `Rational`s, and the sampler computes the same product. The AC-1 and AC-2 tests assert both the sum of 1 and each individual value.
- **Choice-index allocation.** `StepDraws::choose` returns index 0 for a one-item list before it builds a `ChoicePoint` and before it increments `choice`. A one-item choice therefore takes no index and computes no digest, which matches the merged FR-188 and QSpec SM-05/SM-07. The order is operation, then identity, then random parameters in declared position, with each support sorted into canonical value order. The `Coin` test proves that the random parameter takes choice 0 when the other two choices are one-item.
- **Digest preimage.** `DrawPreimage` encodes through JCS. The test checks the bytes `{"choice":"0","draw":"0","seed":"424242","step":"0","trace":"0"}` exactly, and SM-01 to SM-03 reproduce.
- **Total bound.** `with_total` refuses `n > 2^256`, carrying `total`, before any digest is computed. `n = 2^256` is accepted at draw 0 (the SM-08 case, traces 0..49). `Wide` stops the sample with `SampleStop::TotalAboveDrawRange` and a digest count of 0. Weight bit-sizes are already capped at S3 (65,536 bits each, and for the running sum), so the LCM over a support cannot grow without bound.
- **GeneratorMismatch.** `sample` checks it first, before the state key, any expansion and any draw. The digest counter reads 0.
- **Cancel.** Polled at the top of every step, before expansion.
- **FR-187 bounds pre-check skip.** `domains()` skips a random parameter only when its declared type is not enumerable and it has a support. `frames::apply` and `check_rewards` both range that parameter over `Domain::Listed(support)`, so the skipped root is always finite. An enumerable random parameter is still listed by its declared type, which is finite too. The skip is sound. It also closes SR-12213 FND-008: the simulator now ranges over the support rather than the type.
- **Panic and overflow surface.** No `unsafe` was added. The production `expect`s are on proven invariants: a unit-weight remainder below a `usize` count, and divisors proven positive. The choice index uses `checked_add`. `post_states` saturates to `u32::MAX`. The draw counter uses `wrapping_add`, which cannot wrap, because the acceptance probability is at least 1/2.
- **Tags.** FR-187-AC-1 and the reproduction half of FR-188-AC-3 are left untagged because the fixture stands in integers and Booleans for enum and quantity types. That is honest. The other tags match what their tests assert (see SR-12222).

Narrow test run at 9bf872650: `test result: ok. 24 passed; 0 failed` (debug, 0.75 s), covering every new FR-187 and FR-188 unit test. `target/` was deleted afterwards.

| FND-001 | high | Undecided contracts are dropped silently, not stopped. `frames::apply` handles `Conjunction::Undecided` in a precondition by recording a `ContractUndetermined` finding and continuing. `Run::candidates` does the same for a postcondition candidate. `ModelSystem::actions` takes `expand_enabled`'s `Expansion` but never reads `expansion.findings`, and its doc says the structure "does not carry" them. Three consequences follow. A draw with one decided and one undecided candidate looks Markov with 1 post-state. A draw whose only candidate is undecided reports `NotMarkov{post_states: 0}` instead of `ContractUndetermined`. An identity whose precondition is undecided is dropped, and the remaining operations are renormalized. `weighted_steps` and `sample_probabilistic` both inherit this, so EN-4 would settle a probabilistic claim on wrong step probabilities with no signal. FR-187 says an undecided contract conjunction during expansion "SHALL stop with FR-120's `ContractUndetermined`". Fix: when `expansion.findings` holds a `ContractUndetermined`, return a stop (a new `ExpansionStop` cause or a dedicated outcome) from `actions`, which also covers `weighted_steps` and the sampler. Add a test with a postcondition that is undecided for one draw. | qsl-eval/src/simulation/model/probabilistic.rs:495-581; qsl-eval/src/simulation/model/frames.rs:176-192, 1038-1052 |
| FND-002 | medium | An enabled identity with no post-state for every draw disappears. `actions` runs `groups.retain(any draw has successors)`, so a scheduled identity whose precondition holds but whose postcondition is unsatisfiable for every drawn vector is removed. `weighted_steps` then renormalizes over the other operations. If it was the only enabled identity, `weighted_steps` returns the terminal stutter step with probability 1 at a state that is not terminal (FR-124: a state is terminal when no transition identity is *enabled*).
