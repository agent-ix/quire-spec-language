The four author decisions, judged against the code (qsl-*/Cargo.toml, qsl-route/src/lib.rs, qsl-replay/src/proof_result.rs) and against QSpec FR-170, FR-465 and FR-466:

1. Cause type in qsl-foundation `diagnostic`. The X-10 premise is correct: qsl-replay's dependency set has no qsl-route. The placement is still wrong (FND-001). The variant payload `Capability` is in layer 3, and F cannot depend on layer 3. qsl-semantics `check::capability` satisfies both constraints.
2. The "scan of shipped source" is a ceremony-style text check (FND-002). The behaviour oracle already exists in the same AC (code() and the conversion) and in each site's emitted-code tests.
3. PS-7 send-ordered sequence. This is consistent with QSpec FR-170, which says "Queue state is an ordered sequence of message occurrences" and defines `head` as the oldest and `tail` as the newest, and with FR-465 "Queue". The QSL bag is a reduction that QSpec does not require. PS-8's `queues` member carries the contents, so the sequence enters the state key. qsl-eval `Unsupported::UnorderedLossSelector` is the refusal that FR-206's new SHALL NOT retires, and nothing else in the spec mandates it. One ST-4/ST-5 gap is in the failure-domain SR.
4. The ids FR-057-AC-15, FR-519-AC-18/19 and FR-206-AC-12 are free and sequential. TC-155 step 8 and TC-651 step 12 follow the existing steps. FR-519-AC-18/19 match the FR-519 prose apart from FND-005, and FR-206-AC-12 matches AC-7's send-record shape. Structural defects are in the integrity SR.
