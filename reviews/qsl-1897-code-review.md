## Summary

Ticket: QSL-1897 (ADR-036 slice 5). Code review with the rust-review lane folded in, scoped to `git diff origin/main...HEAD`. The reviewer read the code only and ran no cargo build or test, as the brief asks. The lead's decisions are not findings: PA-24 carriage deferred to QSL-1898, the manifest advertising `unbounded` only, the new inconclusive cause words minted in FR-573, and the ItemForm carrier deferred.

Sound parts. The settlement map (`settle.rs`) matches the FR-573 table and QSpec FR-241/242/243/360: `proved`/`closed-scope`/`completed`/`satisfied`/`Uncertified`; `refuted`/`decisive-counterexample`/`completed`/`violated`; `inconclusive`/`unsettled`/`completed`/`pending`; `unsupported`/`unavailable`/execution `unsupported` (a real FR-241 member, and FR-360-AC-4 requires it); `failed`/`unavailable` with `resource-incomplete` or `failed`. `RunLimit.limit` is now the typed `ModelCheckLimit`, so no string gates a branch. The only string reads are the moved `ArenaNames::node`/`channel` edges, which keep `#[ix_trace_rs::string_edge]`. The arena readers moved to `qsl-replay` with their behaviour unchanged. The search, the strategy walk and the new replay arm all compute observation classes with one `Seen::observations`. The item adapters map every refusal variant without a catch-all. The manifest follows the FR-288 pattern of the other engines. Nothing new is quadratic. `arena_names` still searches `graph.nodes` once per id, but that code moved here unchanged. `walk` costs O(initial states × steps × branching), bounded by the stated play. No `/// Trace:` lines. The TL-387 handoff note matches the code: `AnalyzeRecord.protocol_analysis`, `ProtocolAnalysisArtifact::settlement()`, `ProtocolAnalysisKey::from_json` refusing `MissingMember` (`invalid_runtime_input`/`missing-member`), and the `separating_witness` on each counterexample form. It omits only the case covered by FND-005.

The environment-defeat arm is sound for this profile, because every node is an environment node (realize.rs module docs), so any reachable violation decides the result. The indistinguishable-histories arm is not sound: it never checks that the two actions are actually needed (FND-001).

## Verdict

Not mergeable as is. FND-001 is a soundness defect in the realizability replay arm: it can accept a refutation in which neither action is needed. FND-002 and FND-003 should be fixed in the same round. FND-004 to FND-006 are small. Once those are fixed, the PR is mergeable. The settlement map, the manifest, the item adapters and the typed limits are correct.

## New findings (disposition pass 1)

| FND-007 | medium | Both the replay arm and `forced_pair` treat an action that is not enabled at one end as needed elsewhere, so a pair whose enabled sets are disjoint is refuted. The strategy walk lets a role wait: if its committed action is not enabled, the other roles' moves continue (`Some(_) => continue`). Take an end `b` where the role's action `action_a` is not enabled yet: the message has not arrived, or a capacity slot is still full. If another role's step then reaches `b'`, in the same observation class, where `action_a` is enabled, the table `{class -> action_a}` can pass the walk. Yet the engine refutes, and the new arm accepts the refutation, because it checks only that each action is enabled at its own end. That is a false `refuted` passing SM-7. The decision rule predates this PR (QSL-1896 `forced_pair`); this PR's arm reproduces it instead of checking it independently. Fix: at the end where an action is disabled, require it to stay disabled on every continuation that has no step of the role itself, or settle such a pair `unforced`. Deferring to a ticket against the QSL-1896 rule is acceptable. | qsl-replay/src/protocol_analysis/realizability_replay.rs:167-172; qsl-analyze/src/protocol_analysis/realize.rs:965-975, 748-759 |
| FND-008 | low | The engine never produces a non-empty `lost`. Every join is a conjunction over all moves (`every`), so any `Lose` node makes its root `Lose`, and `search` then returns `EnvironmentDefeat` before it looks for forced pairs. At a forced pair, no node is lost, and PA-18 (i) reduces to `enabled_a ∩ enabled_b = ∅`. The `LostAction` construction in `indistinguishable` (with its `debug_assert`) and the arm's continuation branch run only on forged input, and no test exercises a valid continuation. Either simplify to "the enabled sets are disjoint" and drop `LostAction` from the PA-25 shape, or state in the docs why the evidence is always empty when the engine produces it. | qsl-analyze/src/protocol_analysis/realize.rs:777-806; qsl-replay/src/protocol_analysis/realizability_replay.rs:173-203 |
| FND-009 | low | A history whose end is a won leaf one step past `max_history` is refused `BeyondBounds`. The engine checks findings and the terminal class before its history cut, so that leaf is `Win` with `End`, and can be one end of a forced pair. The arm then settles a true refutation `inconclusive` `replay-disagreed`. Make the history bound check match the engine: hold only the expanded prefix to `max_history`, not a terminal end. | qsl-replay/src/protocol_analysis/realizability_replay.rs:158-160; qsl-analyze/src/protocol_analysis/realize.rs:288-307 |


## New findings (disposition pass 2)

| ID | Severity | Summary | Refs |
| --- | --- | --- | --- |
| FND-010 | medium | The sole-mover rule shows that a table committing an action an end does not enable gets stuck at that end, but only if the walk reaches that end. Both ends share the role's observation class, so the role's own earlier steps cannot steer away from one end only. Other roles can. The strategy walk lets every role's table pick among that role's own enabled steps (`Some(_) => continue`), so a role's parallel threads are chosen by its table, not by the environment. If two ends differ in another role's thread order, which the class does not see, that role's table can avoid end `b`. The class is then committed at `a` only, and a winning profile may exist. The engine refutes anyway, and the arm accepts it. This is the same mismatch FND-007 found (PA-16 treats thread order as the environment's move, but the walk lets tables choose it), in a form the sole rule does not cover. The rule predates this PR (QSL-1896 `forced_pair`/walk). Fix: force a pair only when every step on both histories by a role other than the deciding role was that role's only enabled step, or make the walk leave thread order to the environment. Deferring to a ticket is acceptable. | qsl-analyze/src/protocol_analysis/realize.rs:748-772, 930-940; qsl-replay/src/protocol_analysis/realizability_replay.rs:136-185 |
| FND-011 | low | The arm accepts an indistinguishable-histories end, or an intermediate history state, that carries a finding. The engine never makes such a node a decision point: findings make a leaf, and the walk fails there as `NotShown`. A forged counterexample ending at a state with an `Undecided` finding can therefore replay `Ok`: a refutation resting on an undecided evaluation. Refuse an end or a prefix state whose `finding_value` is `Some`. | qsl-replay/src/protocol_analysis/realizability_replay.rs:150-185, 230-250 |
