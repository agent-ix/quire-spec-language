## Summary

Ticket: QSL-1618. Code review with the rust-review lane folded in. The PR adds `NUMBER_MODULE = "number.rs"`, a use-tree leaf walker, and `number_module_violations`, which `scan` applies only to the file equal to `NUMBER_MODULE`: its `pub use` exposures are dropped and replaced by one violation per leaf that is not one of the seven `qsl_package::number::<Item>` paths and per item that is missing or repeated. Other exposure kinds (`pub type`, `pub extern crate`) are still reported, and number.rs still feeds the crate-wide layer-name set. The real `src/number.rs` carries exactly the seven FR-511 items. The existing `the_reexport_scan_catches_every_public_shape` and `the_root_crate_reexports_no_layer_crate_item` are untouched (the diff removes one line, the `exposures(...)` call that is now wrapped). Mutations in a scratch copy: widening to any `.rs`, dropping the whole item-set check, dropping the missing/repeated check, allowing renames, and dropping the `number` path segment each fail a test. Three mutations survive (FND-001 to FND-003).

## Verdict

**NOT MERGEABLE as written, one small fix round.** The implementation is correct against TC-256 step 3 and TC-1306 step 4; the tests do not pin three clauses the spec states. Gate on the trial merge is green except the 9 failures of QSL-1609 (see ticket comment).

- Rust style: `leaf_paths` and `number_module_violations` are small and total; `expect` only in test code; no unsafe; no new dependencies.
