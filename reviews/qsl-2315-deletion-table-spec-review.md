# Spec review of the Layer 4 deletion table (quire-spec-language PR 2315)

## Summary

One pass over `git diff origin/main...HEAD` (head cc19a52b5; PR base 0642337ef, origin/main now 213d8594c, six commits ahead, docs-only overlap none). Reviewer role, spec-review plus architecture-evaluation lens by hand, sampling. Reviewed from a fresh clone; no edits, no push.

Method and results:

- Every `AC=test` pair in all 153 GREEN rows was resolved mechanically against origin/main (408 pairs, 234 distinct test names): 0 missing tests, 404 pairs bound to the claimed AC in the test's `#[trace]` block, 4 pairs unresolved only because the table cell is cut mid-name (`FR-046-AC-7=n`; the real successor is `tests/it/call_requirements_items.rs:868`, tagged FR-046-AC-7, value-asserting on the work and result boundaries). 39 names are cut in the cell and resolve only by prefix, 9 of those prefixes are ambiguous.
- 29 GREEN rows sampled across all five deletion units (4 to 7 per unit); run by name on origin/main (own target dir): 20 successor tests pass (qsl-eval temporal_activation x4, finite_window x2, ledger watermark, protocol_slots, qsl-forms x2, qsl-analyze x2, qsl-semantics x5, qsl-replay `a_header_profile_resolves_by_identity_against_the_root_row`, qsl-package x2, root lib `a_case_that_leaves_the_base_bytes_unchanged_is_a_mismatch` with `--features checked-handoff`). No sampled GREEN successor fails. Tests read for value assertions: activation, guard, origin identity, FR-046-AC-7 (value-asserting); the others were read at the assertion level only.
- The 19 main failures reproduce on origin/main 213d8594c (14 qsl-replay `layers::equality::*` plus `frame_occurrence_region_is_the_first_naming_clause_or_attempt_in_source_order`, `a_family_with_no_body_for_a_concrete_subtype_refuses_at_s3` seen red, `c06_two_selections_canonical_order` red). None is a named successor test. Three sit on requirement FR-110 (see FND-010).
- `quire validate` on the amended FR-362 and ADR-011: exit 0 (only the module duplicate-archetype and inline-data-schema warnings that main also emits). docs/*.md are not catalog artifacts and are not validated.
- Verdict: no high finding. Not mergeable as the gate evidence it is written to be until FND-001 to FND-006 are fixed; docs-only, so merge-then-fix-forward is safe if the lead prefers.

## Verdict

Changes requested, no high finding. The ordering of steps 1 to 4 and 6 to 7 matches FR-499 "Order of deletion" (QSL-838 with QSL-858, QSL-840 with or before, QSL-841 after QSL-840 with six `protocol_artifact/native` files matching `DeclarationKind::Protocol` counted, QSL-868/830 after QSL-837/1508/1509, QSL-499 last). The table's GREEN rows hold up: no sampled or mechanically checked successor is missing, mis-tagged or failing. The risk is the gate text (FND-001, FND-002, FND-003) and the NO-SUCCESSOR list (FND-005 to FND-007), which overstates the owner's decisions by roughly 25 rows and hides four real untagged-but-Done gaps (FR-507, FR-509). Reclassification target after fixes: about 18 real NO-SUCCESSOR rows.
