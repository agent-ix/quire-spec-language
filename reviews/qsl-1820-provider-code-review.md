## Summary

Independent frozen-head code and Rust review of the canonical SourceProvision/NegotiatedItem/ProviderResults cutover. Two concrete value-routing/accounting defects require fixes.

## Verdict

FAIL for the current candidate. A selected external provider can be bypassed by native execution. Existing external integration boundaries remain stated partial work.

## Findings

| ID | Severity | Summary | Refs |
| --- | --- | --- | --- |
| FND-001 | high | Canonical value-validity work always calls value_item, even when Supported names a registered Engine::external. That closure never invokes the selected provider: a valid unbounded Integer division claim reaches native RequiresBound/unsupported instead of the provider's verdict. A descriptor also advertising bounded mode can receive a native verdict attributed to its external BackendId. Select the existing external_provider::provider_item adapter for external candidates and test callback invocation, verdict/provenance, replayed counterexamples and cancellation through both public entries. | qsl-analyze/src/analyze/request.rs:453-474 |
| FND-002 | medium | The new value-validity adapter keeps ValueTarget::select's AccountingLimits::default() instead of applying limits.accounting. The native evaluator therefore ignores the operation's requested accounting budget, and an explicitly unbounded operation still inherits the default cap. Apply the existing ValueTarget::with_limits at target construction and add a real bounded-value request whose small accounting limit stops it, with an adequately funded control. | qsl-analyze/src/analyze/request.rs:469-472 |
