## Summary

Ticket: QSL-567. PR: quire-spec-language#1084, head 0455abebf, scoped to `git diff refs/remotes/origin/main...0455abebf` (one commit, three files, +18/-7). Spec-only. It replaces the whole-SCC visibility-fairness rule of ADR-025 MF-2 and FR-228, under which a load-free sub-cycle of an SCC with a stale load was rejected (a false `proved`, SR-12218 FND-001 on code PR #1080), with an edge Streett condition decided by recursive SCC decomposition. It also restates MF-5, changes FR-228's Description, Behavior and AC-3, and adds FR-228-AC-5 and TC-673 step 5. Base review: soundness of the edge Streett decomposition, machine closure, agreement with the lasso form, the AC-5 example, and AC testability. Independent checks. (1) Exactness of the decomposition, by brute force: sr-1084-tools/streett_oracle.py builds random graphs (1 to 5 states, up to 9 edges, self-loops and parallel edges), 1 to 3 visibility pairs with random R and G ⊆ R, a random accepting set and, in half the cases, one weak constraint. The oracle enumerates every edge set, keeps the nonempty strongly connected ones (exactly the edge sets of closed walks), and applies the per-loop (lasso) check. The decomposition is MF-2 with FA-4's acceptance and weak tests. Over 21,000 cases (seeds 1 to 5) the two agree on every case: 0 mismatches, about 40% of cases fair. Removing every failing pair's R at once (FR-228's wording) also gives 0 mismatches in 6,000 cases. The old whole-SCC rule rejects a graph that has a fair cycle in 461 of 6,000 cases (a false `proved`), and it never accepts a graph with no fair cycle. For every passing SCC, the closed walk that covers all of its edges passes the per-loop check, so the SCC form and the lasso form agree. The proof by hand: a closed walk lies in one SCC. A passing SCC holds a covering walk, which takes a G edge for every pair whose R it touches. A fair walk in an SCC with R_i but no G_i takes no R_i edge, so removing R_i loses no fair walk. A failing acceptance or weak test is inherited by every sub-SCC, so rejecting there is exact. Each removal drops at least one edge and empties R_i below it, so the recursion ends, with depth at most the number of pairs plus one. (2) Machine closure: RA-2 lets a load read any message at or after cur_b(ℓ), and the mo-last message always qualifies. An RMW may read it (it has no attached successor). An SC read of it adds no outgoing fr edge, so P stays acyclic and the choice is never pruned. So wherever an R edge is enabled, a G edge is too, and MF-3 holds. (3) AC-5 checked by hand and by the script: R = {q→r}, G = ∅. Removing q→r leaves p→q, q→p and r→q, with SCCs {p,q} and {r} (trivial). {p,q} is accepting and holds no R edge, so it passes. The whole-SCC rule rejects. (4) Repository grep: MF-2, MF-5, 'weak rows', FA-4, CX-5, FS-2, FS-6, FS-7, PC-4, FR-339, FR-126 certificates, TC-673. (5) QSpec PR #294 states the same rule and the same p q r example (AC-7, LT-12). QSpec main FR-437 still states the whole-SCC rule. (6) Code PR #1080 (qsl-567-impl, 18c9bafd2) already has `ComponentWitness::UnfairVisibility{constraints, sub}`, under which an edge a visibility refinement removed is in no rule below it. No spec defines that witness. Methods: spec-review/base (SR-13401), spec-review/ears (SR-13402), spec-review/integrity (SR-13403). code-review and gap-analysis were not run, because no code or test file changed. Gates on the head: make check-spec-validation exits 0 with 17 warnings, the same as main 47047b1df, none in the changed files. tools/check-index-completeness.sh passes. quoin 0.28.3, quire 0.36.2 (engine 0.50.2), newer than the rollout note's 0.36.1/0.50.1.

| FND-001 | high | The corrected rule has no certificate. A `proved` TP-4 item is `Certified` only after the qualified core's component check (ADR-018 PC-4, FR-339) accepts it. FR-339's witnesses are `Trivial`, `MissingAcceptance`, `UnfairWeak` and `UnfairStrong`. `UnfairWeak` needs a constraint 'enabled at every state of the component', which does not fit a visibility pair, and it would also certify the old unsound whole-SCC rejection. `UnfairStrong` removes states, not edges. Neither ADR-025, ADR-018 PC-4, ADR-019 AM-7, FR-339 nor FR-126's Certificates section defines a witness for MF-2's edge removal. Such a witness must state three things: (a) the pairs it names each have an R edge and no G edge inside the component; (b) `sub` partitions the component's states over the subgraph without those R edges; (c) a removed edge is exempt from `BackwardEdge` and from every witness below it. In AC-5, after `q → r` is removed, `{r}` must come before `{p, q}` (`r → q` remains), so the removed `q → r` runs backward. Without (c) a correct certificate is rejected. Code PR #1080 already implements this as `UnfairVisibility{constraints, sub}`, so the code and the checker are ahead of a spec that does not define the rule. AC-5's last sentence ('The certificate check of the same SCC accepts the same decomposition') asserts a check with no contract. Also, FR-126 issues a certificate only for an item that holds, and AC-5's claim is `refuted`. Fix: add the witness to ADR-018 PC-4 (as an ADR-025 amendment), FR-339 and FR-126's certificate order. ## Verdict

Not mergeable yet. One high finding (FND-001: the certificate has no witness for the edge removal) and two medium ones (FND-002: the passing component and CX-5's walk must use only the edges the decomposition kept; FND-003: AC-5's vector). What holds, and it is the core of the fix: the edge Streett decomposition is exact. A fair closed walk exists if and only if the recursive decomposition finds a passing non-trivial SCC; brute force over 21,000 random graphs with up to 3 pairs, acceptance and a weak constraint found no mismatch. Removing a failing pair's R edges loses no fair walk. The recursion ends. The SCC form and the lasso form agree. The constraint is machine-closed. The AC-5 example is right. The old whole-SCC rule is unsound in about 8% of random cases, a false `proved`, so the correction is needed. Merge order: FR-228 reads visibility fairness 'as QSpec FR-436 and FR-437 define it', and QSpec main still states the whole-SCC rule, so merge this PR with or after QSpec #294.
