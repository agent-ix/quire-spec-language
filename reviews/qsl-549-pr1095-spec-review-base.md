## Summary

Ticket: QSL-549. PR: quire-spec-language#1095, head 5fc5e5eb5, scoped to `git diff refs/remotes/origin/main...5fc5e5eb5` (one commit, two files, +69/-21). Spec-only. Base review: each new FR-149 rule against the merged FR-141, FR-144, FR-338, ADR-018 and ADR-020 text and the #1089 checker. The PR is the spec follow-up to code PR #1089 (head ba1d01ad2; no fix round is pushed yet, the PR has that one commit), and answers SR-13430 FND-003 to FND-007 and SR-13431 FND-002. Each new rule was checked against the merged text and the #1089 code. Matches: `CertifiedEdge.transition: Option<ModelTransition>` with `None` as the SM-4 stutter is what the code writes, and a refinement is always under an infinite-trace profile (ADR-020's `refinement <Name> using <infinite-trace profile>`, FR-142's stutter edge), so an unconditional stutter edge is right. `FailedStep` restricted to Fails/Undefined/Undetermined is the code's type; the six wire kinds are the code's `FailedStep::kind()` strings, and `Fails(RefinementFailure::Undefined)` cannot come from `check_step` (FR-141: the engine writes it from `StepVerdict::Undefined`), so the six cover every reachable verdict. SuccessorsDiffer comparing transitions only and PostDiffers judging post and `Taken` is what the code does and what AC-2 needs; ADR-020 CT-2 (b) and (c) still read true. `Stopped(IncompleteCause)` with `LimitReached{limit, value}` / `Cancelled{source}` matches `TemporalCertificateCheck::Stopped` and the code's `IncompleteCause` on main. BadState as 'a concrete contract undecided' is the code's `ContractUndetermined` guard and FR-338-AC-3's meaning. Does not match: the wire locus. #1089's serializer writes `position` as a JSON number and `verdict` as the bare kind string; FR-149 now asks for decimal strings and a kind-plus-fields object. That is the owner's decision and an implied code change the PR body lists, not a spec defect. FND-003's own reproduction (SR-13430) had the meter run out in `check_initial` at work 1 and 5 (`InitialMismatch`) as well as in a mapping row at work 50 and 100 (`StepFails`); the new Meter stops rule covers only the second (base FND-001). Gates on the head: make check-spec-validation exits 0 with 17 warnings, the same count as on main, none in FR-149 or TC-556. tools/check-index-completeness.sh passes. quoin 0.28.3, quire 0.36.2 (engine 0.50.2). Methods: spec-review/base (SR-13480), spec-review/ears (SR-13481), spec-review/integrity (SR-13482). code-review and gap-analysis were not run, because no code or test file changed.

SR-13430 FND-003 reproduced exactly this: the light `RingIsQueue` certificate at work 1 and 5 gives `Rejected{InitialMismatch, position 0}`. ## Verdict

Not mergeable. The PR settles SR-13430 FND-004 (stutter edge), FND-005 (`Stopped` shape), FND-006's typing and FND-007 (Malformed and BadState listed; transitions-only `SuccessorsDiffer`) correctly, and each of those matches the #1089 code and the merged FR-338, ADR-018 SM-4 and ADR-020 CT-2 text. FND-003 is only half fixed: a meter stop in `check_initial` still rejects (FND-001), and the new meter clause of AC-5 cannot be exercised by `HeavyEnq` (FND-002). The static unreached-position rule leaves a gap the index-order check falls into (FND-003). The meter rule needs a cause the FR-141 verdict does not carry (FND-004). The package identity rule has no AC (FND-005). The wire verdict's fields are named only for one kind (FND-006), and its spellings belong on the QSpec half (FND-007). The owner's decisions, kind plus fields on the wire and the package-id comparison in FR-144, are followed as decided; the findings are about stating them completely.
