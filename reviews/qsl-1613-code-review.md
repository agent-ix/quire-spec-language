## Summary

Ticket: QSL-1613. The PR replaces the package-wide further-alias spelling tables with `ModelSpellings`, which holds each package's type names by member and each unit's model aliases. Every `Scope` type-name lookup (`named_types`, `object_type_named`, `variant_type_named`, `variant_case_named`) now takes the source unit, through a new `SourceScope` that implements `TypeNames`. The assembler's `Names` no longer carries model types, and it resolves through a per-unit `UnitNames` view. Every changed signature is enforced by the compiler: `Scope` and `Names` no longer implement `TypeNames`, so no call site can skip the unit. The design is sound. Doc comments and FR-480 references are accurate, apart from FND-004.

One unit is missing from the alias map (FND-001). Two kinds of remaining unit-blind lookup were also found. First, the timed-model checks build their clause views with `source_owner: None` and a check context that has no owner. Before this PR such a lookup read a package-wide table. It now reads the primary unit's aliases, which is a regression for non-primary units (FND-002). Second, several alias-keyed joins pick a model by alias string alone. These were already on `main`, but this PR makes the "same alias, two packages" layout a supported, specified case (FND-003).

## Verdict

**CONDITIONAL (blocking).** FND-001 is a high regression: two units that select one package under the same alias, which is the ordinary multi-unit layout, now fail to assemble. Two existing `qsl-replay` tests fail on this head. FND-002 is a second behaviour regression against `main` that this PR introduces, and it contradicts the new FR-480 sentence "in every position a type name is written". Fix it in this PR, or narrow the spec sentence and ticket the gap. FND-003 can be deferred to a follow-up ticket. FND-004 and FND-005 are low.
