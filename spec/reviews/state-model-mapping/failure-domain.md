# SR-788: Failure-domain review of ADR-016 state, model and finite execution mapping

## Summary

Reviewed ADR-016 on `spec/19-arch40-mapping` at commit `47b1b806`, and its
amendments to the ADR-012 Status paragraph, the ADR-013 §6 Outcomes row, the
FR-089 Status paragraph and `spec/spec.md`. The review applied the four
failure-domain checks: extension points, entity identity, evaluation purity
and topological robustness. Each code claim was opened at its file and line
on the worktree, which is QSL `main` `99e9b6c7` plus the ADR commit.

What holds:

- The cited code locations are correct. This covers `mint_population_id`,
  `ObjectEnvironment::with_population`, `ModelCorrespondence`,
  `resolve_declaration`, `link_dispatch`, `normalize`, the evaluator's
  `AllInstances` and `Lookup` arms, `ProtocolClauseUnsupported`, the two
  `S6aFamilyKind` variants, `explore`/`explore_request`, `Outcome::category`,
  `SampleProvenance{seed, trace, sampler, stopped}`, `run_clause`,
  `replay_frame` and the four `TransitionSystem` test fixtures.
- Every TC the ADR cites exists: TC-198, TC-222, TC-225, TC-291, TC-439,
  TC-455, TC-467, TC-469, TC-471 to TC-474, TC-514 and TC-515.
- FE-4 holds. `ValueTypeRef` has only `Native` and `Package` variants
  (`qsl-semantics/src/model/domain_package.rs:150-155`), so no clause source
  produces a `Population` value.
- Cancellation, depth, state and transition limits are total in `explore`,
  and it terminates on cycles because it coalesces by key bytes.

What does not hold:

- One finding is high. The ID-5 decision says the declared maximum cannot
  differ between two admissions. In the code it is a caller argument, and
  the binding's equality also covers caller limits and the pre anchor. So
  the conflict that ID-5 turns into an `InternalFault` stays reachable.
- The other findings are gaps in identity (content scope, the synthesized
  `DocumentRef`, simulation envelopes, root keys, the correspondence map),
  vacuous `Exhaustive` results, the ND-1 pruning rule, an unmetered walk
  inside the one frame decision, and the agreement rule's grounding.

## Findings

| ID | Severity | Summary | Refs |
| --- | --- | --- | --- |
| FND-001 | high | ID-5 says the declared maximum "cannot differ between two admissions" because it is read from the declaration. The code does not do that. `admit_binding` takes `declared_maximum: Option<u64>` from the caller (`qsl-semantics/src/model/population.rs:811`, and `InvocationContext.declared_maximum` at `:1175`). `PopulationBinding` derives `PartialEq` over `declared_maximum`, `ancestor_steps` (the caller's `PopulationAdmissionLimits`), `pre_anchor`, `index` and `type_catalog` (`population.rs:550-599`). After G-3, two admissions with equal package, key, role and members but a different maximum or `ancestor_steps` mint one `PopulationId`, yet the bindings are unequal. The same holds for two `Post` bindings with equal post members and different pre documents (`admit_invocation` attaches `pre_anchor`, `:1275`). So `with_population`'s refusal (`object_environment.rs:156-163`) is still reachable by a caller, and it is not an `InternalFault`. Fix: in G-3, either read the maximum inside `admit_binding` from the view's `PopulationRecord` and delete the parameter, or add it to the preimage. Take `ancestor_steps` out of binding equality, or add it to the preimage. Add the pre binding's `PopulationId` to the `Post` preimage. Keep `PopulationConflict` a typed refusal until each case is closed. Add these three cases to G-3's acceptance criterion and to TC-291. | ADR-016 §2 ID-5, §9 G-3; FR-089; `population.rs:550-599`, `:811`, `:1175`, `:1275`; `object_environment.rs:156` |
| FND-002 | medium | "Population identity binds its content" overstates what `members` covers. The member set is `(ReferenceKey, DeclarationKey)` pairs (`population.rs:556`), which hold object identity and most-specific type but no field values. Two admissions of the same objects with different field values mint the same `PopulationId`. The ADR does not say what detects two different field states for one `ObjectReference` in one evaluation. Fix: state that `PopulationId` identifies membership and not field state. Name the check that refuses a second, unequal object record in `ObjectEnvironment`, or add a field-values digest to the preimage. | ADR-016 §2 ID-5, Alternatives ("the member set is the content that matters") |
| FND-003 | low | The `members` preimage member has no wire shape. The ADR says "the RFC 8785 JCS digest ... of the admitted binding's member set" but does not fix the JSON form of a pair, the spelling of `ReferenceKey`'s `UniverseId` and `EffectiveId` (hex or bytes), the digest algorithm and encoding of the nested digest, or the value for an empty population. Two implementations could mint different ids for equal content. Fix: give the typed wire form (for example `[{"reference": {"universe": <hex>, "type": <hex>, "object": <text>}, "declaration": <DeclarationKey wire>}]`), the digest encoding, and the empty-set case in ID-5 or in the FR-089 amendment. | ADR-016 §2 ID-5; FR-089 |
| FND-004 | medium | ID-10 gives a simulated state a `DocumentRef` named by its state-key digest. The state key omits the anchor (EX-2), and FR-120 anchors each step of a sampled trace to that step's own transition. So one ID-10 `DocumentRef` names observations with different anchors. ID-7 says an observation is identified by the `sha256-jcs` digest of the document bytes, and FR-106 documents carry `anchor` (FR-106 line 137). The ID-10 digest is not a digest of any document bytes, so ID-7's rule "bytes must match" cannot apply to it. Fix: state that a simulated observation's identity is the pair (ID-10 ref, anchor), that an ID-10 ref is never resolved through an FR-106 byte provision, and that every finding and run report carries the anchor next to the ref. | ADR-016 §2 ID-7, ID-10, §3 EX-2; FR-120 "State, state key and anchor"; FR-106 |
| FND-005 | medium | A simulation finding carried as a counterexample envelope has no minter and no position. §6 says such a finding is `ReplaySource::Input`. ID-11 names CG as the only minter of a `WitnessEnvelope`. EX-5 fixes `trace_position: None` for state-family envelopes. A sampled-trace finding at step k then has no field for k, and no component builds the envelope. Fix: either state that a simulation finding never becomes a `WitnessEnvelope` and replays only through FR-101 `replay`, or name the minter and the field that carries the step index and the ID-10 ref with its anchor. | ADR-016 §2 ID-11, §3 EX-5, §6 third bullet; ADR-013 O-25 |
| FND-006 | medium | `Exhaustive` can be vacuous, and §6 does not define a "clean" run. `explore` returns `Exhaustive` with zero states for an empty initial set (`qsl-eval/src/simulation/explore.rs:150-240`; the `explore_request` doc at `:268` says it never returns `EmptyInitial`). A universe with zero objects makes every invariant hold trivially. A meter budget of zero gives `Exhaustive` with every invariant `InvariantUndetermined` (FR-120-AC-6). §6 says "a clean `Exhaustive` run means no violation found within this request". Fix: define a clean run as `Exhaustive` with at least one state and no finding of any kind, violated or undetermined. State whether `explore_model` refuses an empty initial set, as sampling does with `EmptyInitial`. Require the report to show each universe's object count, so a zero-object universe is visible. | ADR-016 §6, §3 EX-7, EX-9; FR-120-AC-6; `explore.rs:150-240`, `:268` |
| FND-007 | medium | ND-1 says "nothing prunes [a choice] except a false effective pre- or postcondition". FR-120 prunes on more than that. An `Undefined` precondition makes the operation not enabled and records `ContractUndetermined` (FR-120-AC-9). An undetermined postcondition gives no successor. A frame check refuses candidates. `max_candidates` stops the expansion (FR-120-AC-6). So an `Exhaustive` run with undetermined findings did not enumerate every authored choice. Fix: list every prune cause in ND-1 (false, undefined with its finding, frame refusal, `ExpansionStop`). State that an undetermined prune is always a finding, so such a run is never clean (FND-006). | ADR-016 §5 ND-1; FR-120-AC-6, AC-9 |
| FND-008 | medium | The one frame decision contains an unmetered walk. FE-1 routes every frame check through `population::decide_frame`, which uses `redefinition_reaches` (`qsl-semantics/src/model/index.rs:597-617`). That walk is bounded only by the record count and charges nothing. Linear QSL-48 (Backlog, read as data) puts its cost at about writes × records². Under G-4, `check_frame` runs it for every candidate successor of every state, and EX-6 polls for cancellation only between states. A redefinition cycle also returns `false` (`index.rs:616`), so it is reported as a frame violation rather than as a malformed model. Fix: add the QSL-48 meter to the gap table as a prerequisite of G-4, with a charge point. State that normalization refuses a redefinition cycle (FR-082), so the `false` branch is an internal fault. | ADR-016 §4 FE-1, §3 EX-6, §9 G-4; FR-082; `index.rs:597-617`; Linear QSL-48 |
| FND-009 | medium | The agreement rule is weaker than FR-082, and its cycle argument rests on the wrong stage. FR-082-AC-6 says "Anything check time admits, evaluation completes" under a shared `ancestor_steps` ceiling, and TC-219 and TC-220 test that. ADR-016 allows S6a to return `resource_exhausted` on a chain that check admitted, because the binding uses the caller's `PopulationAdmissionLimits::ancestor_steps` (`population.rs:570-573`). The ADR says a cycle "cannot reach S6a because S3 refuses the type environment first". But S6a model views are normalized again from provision bytes (FR-106, FR-120 `StateModel::new`), apart from S3. They are safe only because normalization itself refuses cycles (FR-082) and because the provision digests must match the checked package's selections. Fix: choose one rule. Either amend FR-082-AC-6, or require the S6a `ancestor_steps` to be at least the check-stage ceiling. Cite TC-219 and TC-220 in OR-2 in place of "a new agreement test". Ground the cycle claim on normalization and the digest match. | ADR-016 §1 agreement rule, SC-6, §10 OR-2; FR-082-AC-6; `population.rs:570-573` |
| FND-010 | medium | SC-1, SC-2 and §8 state as present fact behavior that open gaps contradict. SC-1 says S3 decides whether a relationship end exists, but no FR-085 resolver exists (G-5). §8 says the implemented behavior conforms on stage placement. But `normalize` never calls `check_field_redefinition`, `check_operation_redefinition` or `check_subsetting` (`qsl-semantics/src/model/conformance.rs:188`, `:266`, `:345` have no caller), so a model whose redefinition breaks variance still normalizes (Linear QSL-56, Backlog). SC-2's total conformance relation is then computed over an effective view that admits invalid redefinitions. Fix: mark SC-1's relationship-end case as available after G-5. Add QSL-56 as a gap row. Qualify §8. | ADR-016 §1 SC-1, SC-2, §8; FR-082; FR-085; `conformance.rs:188`, `:266`, `:345`; Linear QSL-56 |
| FND-011 | low | The two population keyings share one type. §2 says no conversion exists between the requirement-record `DomainKey` and FR-120's simulation root. Both carry a `WireNodeId`, so nothing in the types stops a simulation root being passed into a `DomainKey` or a `ProofBound`. §2 also covers only population roots, not FR-120's parameter, result and field roots. It says "a caller answers a simulation `RequiresBound` with universes", which is false for a parameter root typed `Integer` (FR-120-AC-7): only a bounded type in source answers that. Fix: give simulation roots their own newtype, or name the test that shows no simulation root reaches `route`, CG or FR-331. Extend §2 to parameter, result and field roots, and say what answers each. | ADR-016 §2 "Two keyings", §3 EX-1; FR-120 "Bounds", FR-120-AC-7; ADR-012 §15.7 |
| FND-012 | low | ID-1 and ID-3 make the model correspondence the only crossing from `NodeKey` to `DeclarationKey`. `ModelCorrespondence::record` uses `BTreeMap::insert` (`qsl-semantics/src/check/identity.rs:270-272`), so a second record of one `NodeKey` with a different `DeclarationKey` overwrites it silently. Nothing states that the map is injective in the other direction. Fix: state that the correspondence is injective both ways, and that a re-record with a different key is an internal fault. Back it with a test. | ADR-016 §2 ID-1, ID-3; `check/identity.rs:257-280` |
| FND-013 | low | EX-6 does not bound how long cancellation can take. `poll` runs once per state (`explore.rs:184`). One expansion runs every clause evaluation for every candidate, each with a fresh meter, so the work between two polls is bounded only by `ExpansionLimits` × the meter budget, plus the unmetered walk of FND-008. Fix: state that bound in EX-6, or have G-1's `Expansion` poll per candidate. | ADR-016 §3 EX-6; `explore.rs:184` |
| FND-014 | low | The ADR-013 §6 amendment keeps "the lane-D simulation `Outcome` before convergence", but the root crate has no simulation code (`grep -rl simulat src/` finds nothing). The §6 intro still says lane D's outcomes "are the kernel `Outcome`", which contradicts FP-4 (`qsl_eval::simulation::Outcome` is canonical). The Consequences bullet "Lane D converges when G-4 lands" then names a lane with no remaining code. Fix: delete the lane-D entry from the row, amend the §6 intro sentence to name `qsl_eval::simulation::Outcome`, and restate the Consequences bullet. | ADR-013 §6; ADR-016 §7 FP-4, Consequences |
| FND-015 | low | Two citations are wrong. ID-5 says `admit_binding` "is called only from tests", but `qsl-bench/src/model.rs:309` calls it too. ID-5 cites "FR-089's open question (Linear QSL-131)", but Linear QSL-131 is "Replace the QSL value kernel with quire-exact and remove the negotiate_* copies" (Done); GitHub #131 is Linear QSL-64. Fix: name both callers, and cite the ticket that actually holds the open question. | ADR-016 §2 ID-5; `qsl-bench/src/model.rs:309` |

## Disposition

Every finding above is fixed on `spec/19-arch40-mapping` in the ADR-016 rewrite and its listed amendments (ADR-011 M-6c and §8; ADR-012 §2, §3, §5.1, §13.5; ADR-013 O-13, T-6, QC-21, O-16, §6; FR-089; FR-120; `spec/tests.md`), except as noted below.

- FND-011: partly declined. A simulation root and a `DomainKey` stay the same `WireNodeId` type, because no API accepts one where the other is expected: FR-101 takes `(WireNodeId, &ValueType)` roots only, and `route` takes requirement records only. ADR-016 §2 now covers every root kind and says how each `RequiresBound` is answered.
- FND-002: fixed by stating that a `PopulationBinding` carries membership only and that field values belong to `ObjectEnvironment` (ADR-016 ID-5, FR-089). No field digest is added.
