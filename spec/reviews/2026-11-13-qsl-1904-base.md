# SR-2699001: Base and correctness review of QSL-1904 field-edge reachability population link

## Summary

Ticket: QSL-1904. Base checklist plus a correctness and soundness lens over
`git diff origin/main...HEAD` of PR #2699: FR-380's new section "Field-edge
reachability" and FR-380-AC-8 to FR-380-AC-14, the FR-105 `reaches_field`
member note, and TC-1054 rows 15 to 21. Read against FR-104 (field-edge
admission and requirements), FR-365 ("The population a reachability walks",
"The population link", FR-365-AC-13), FR-576 (no interaction: `reaches`
outside a clause refuses), the code gate at
`qsl-semantics/src/check/state_clause.rs:1049-1075`, the field lowering at
`qsl-semantics/src/check/lowering.rs:5412-5442`, and QSpec FR-322 "Reaches
over a field" and "Population link of a `reaches`" (FR-322-AC-73), cited by
id only. `quire validate` is clean on the three changed files.

What holds:

- **The operand-type claim is true.** `walked_object`
  (`state_clause.rs:739-744`) returns the source operand's static type for a
  `NodeKind::Reaches`, and the link gate (`state_clause.rs:1065`, `end_form
  &&`) links only `ReachesEnd`. The `reaches_field` lowering names the member
  `declaration` by the same operand type (`lowering.rs:5420-5421`).
- **What changes under `complete/v1` for a subtype operand.** Over fixture R
  (only `orders` of `Order`), nothing changes in the record:
  `population_of(Rush)` and `population_of(Order)` both return `orders` with
  its canonical member `Order` (`state_clause.rs:675-703`, `model.rs:1308-1326`
  covers by `target` conforming to a member), and `walked_bound` returns the
  same bound. The rule changes the node's `E` (lowering must take `T`, not the
  operand or the member's `declaration`, which is `Rush`), and it changes the
  record only where a population covers the subtype but not `T` (FND-003).
  Taking `T` is the sound choice: the walk visits `T` objects, which a
  population covering only the subtype need not contain.
- **Node keyed `(T, N)` sharing** agrees with "The population node" and FR-365
  "The population link": one content-addressed node, one `Type` occurrence per
  bound. FR-380-AC-14 and TC-1054 row 21 test it.
- **Key absent when no bound** keeps node identity: TC-1054 row 19 correctly
  removes the added fields before comparing with TC-1047 row 3, since adding
  `chief`, `chain` and `pair` changes the `Order` node.
- **The stale-sentence correction is right.** The removed sentence said a
  field-edge `reaches` walks no population. The code already adds the
  field-edge walked population to the record (`state_clause.rs:1049-1073`) and
  derives the evaluation bounds from every claim population
  (`state_clause.rs:1102-1108`), as FR-104 "Requirements" states.
- The QSpec FR-322 conflict (no member kind other than `relationship_end`
  carries `population` today) is recorded as an upstream amendment;
  FR-380-AC-11 reads through it. Only its wording is a finding (FND-005).

Verdict: not mergeable until FND-001 to FND-004 are fixed in this PR; the
lows are wording and coverage.
