# TC-778: The interpreter implements the execution seam, and the seam admits checked input only

## Description

Verify the `ExecutionBackend` seam with the interpreter and a test backend.

Scope: FR-294-AC-1 to FR-294-AC-7.

## Test Procedure

1. Prepare the interpreter backend over FR-100-AC-4's unit with every function selected and call each AC-4 case; call `CheckedPackage::call` with the same inputs. Evaluate FR-109's ConfigVersion clause through `evaluate` and through `CheckedPackage::evaluate`.
2. Compile the `compile_fail` doctests that pass package bytes, a `ParsedSource` and an unchecked expression to `prepare`, and file bytes to AOT's `generate` step, beside compiling controls.
3. Prepare a test backend standing in for `jit` that cannot run the third of three selected entries; read `unsupported`, and call all three entries.
4. Call `prepare` and `call` with a handle already cancelled.
5. Read `PrepareLimits::default()`. Prepare a test backend that charges one compile work unit per entry over three entries with `compile_work_units` 2, then with the default; prepare the interpreter over the same entries with both fields 0.
6. Prepare a charging test backend that follows FR-294's "Prepare charges" over FR-262-AC-1's `count` with an observer recording charges; repeat with `compile_work_units` one below the body's node count, with `code_bytes` one below the generated byte total, at exactly each count, and cancelled with `Requested` from a second thread after 3 observed charges.
7. Prepare a test JIT that does not translate `let`, has no `Decimal` representation and does not implement one operation, over three entries whose first untranslatable constructs are a `let`, a `Decimal` parameter and that operation's application, and over an entry with a `let` after the operation application.

Tag the tests `#[trace("TC-778", "<AC id>")]`.

## Expected Results

- Step 1: each pair of results is equal.
- Step 2: the doctests fail to compile and the controls compile.
- Step 3: `prepare` returns `Ok`; `unsupported` lists the third entry alone with `UnsupportedEntry { backend: Jit, cause: Untranslatable { construct, location } }`; the first two calls return their interpreter results and the third returns `CallFailure::Unsupported` with the same `UnsupportedEntry`.
- Step 4: `PrepareFailure::Cancelled` and `CallFailure::Cancelled`.
- Step 5: defaults 16777216 and 67108864; `PrepareFailure::Limit` naming `prepare.compile_work_units`, configured value 2, counter 3; then `Ok`; the interpreter returns `Ok`.
- Step 6: one `compile_work_units` charge per translated body node before it, one `code_bytes` charge per kept block equal to its length before it is kept; `PrepareFailure::Limit` naming `prepare.compile_work_units` then `prepare.code_bytes`, each with its bound and counter; `Ok` at exactly each count; `PrepareFailure::Cancelled(Requested)`, no prepared value, at most one charge after cancellation.
- Step 7: `Untranslatable` with `ExpressionForm("let")`, `ValueType(Decimal)` and `Operation(k)`, each with its construct's `location`; the mixed entry names the operation.
