# TC-778: The interpreter implements the execution seam, and the seam admits checked input only

## Description

Verify the `ExecutionBackend` seam with the interpreter and a test backend.

Scope: FR-294-AC-1 to FR-294-AC-7.

## Test Procedure

1. Prepare the interpreter backend over FR-100-AC-4's unit with every function selected and call each AC-4 case; call `CheckedPackage::call` with the same inputs. Evaluate FR-109's ConfigVersion clause through `evaluate` and through `CheckedPackage::evaluate`.
2. Compile the `compile_fail` doctests that pass package bytes, a `ParsedSource` and an unchecked expression to `prepare`, and file bytes to AOT's `generate` step, beside compiling controls.
3. Prepare a test backend that cannot run one of three selected entries, and call the two it prepared.
4. Call `prepare` and `call` with a handle already cancelled.
5. Prepare a test backend that cannot translate one expression form over three entries, the second using that form and the third using an unrepresentable value type; prepare it again over only the second and third; serialize each `UnsupportedEntry` in an FR-286 document; prepare the interpreter over the same three entries.
6. Prepare a charging test backend over FR-262-AC-1's `count` with `prepare.work_units` one below its translated node count, then `prepare.code_bytes` one below its generated byte count, then each at exactly its count; read `PrepareLimits::default()`; prepare the interpreter over `count` with both fields at 0.
7. On step 5's three-entry prepared value, `call` the second entry and `evaluate` a clause entry the backend lists as unsupported, with a meter recording admitted charges, then `call` the first entry.

Tag the tests `#[trace("TC-778", "<AC id>")]`.

## Expected Results

- Step 1: each pair of results is equal.
- Step 2: the doctests fail to compile and the controls compile.
- Step 3: the prepared value holds two entries and the failure names the third `Unsupported`; the two calls return their interpreter results.
- Step 4: `PrepareFailure::Cancelled` and `CallFailure::Cancelled`.
- Step 5: `unsupported()` lists the second entry's `ExpressionForm` with its form and `Location`, then the third's `ValueType` with its type and first node's `Location`; the two-entry selection returns `PrepareFailure::Unsupported` with the same two values in order; each serializes with `unimplemented_capability`, category unsupported, exit 21; the interpreter lists none.
- Step 6: `PrepareFailure::Limit(LimitExceeded)` with `work-budget-exceeded` and `prepare.work_units`, then `input-bytes-exceeded` and `prepare.code_bytes`, each with its bound and would-be count, no prepared value, exit 22; at exactly the count both succeed; the defaults are 16777216 units and 67108864 bytes; the interpreter prepares with both at 0.
- Step 7: both return `CallFailure::Unsupported` with exactly the listed `UnsupportedEntry`, no admitted charge and no body invocation, category unsupported, exit 21; the first entry returns the interpreter's result.
